# 开发约束 —— trunk 冻结 + 十条铁律

> 配套 `../README.md`。本文讲**为什么**这么定、**怎么强制**、**怎么自检**。
> 一句话：**能交给工具的规则，就不要只写在文档里。**

---

## 0. 为什么必须有一份"硬约束"

这次的开发形态有三个特点，决定了靠"记着"一定出事：

| 特点 | 后果 |
|---|---|
| **trunk 是唯一原件，且无版本管理** | 一次误覆盖 = 从 5.8 GB 的 `trunk.rar` 重来 |
| **要搬 22.7k 行 + 改 53 个原文件** | 分不清"这行是原版还是我改的"，就没法定位问题 |
| **会连续几个月反复试错** | 三个月后没人记得"为什么这行要这么写" |

所以能强制的必须强制，只有**强制不了**的才写进文档。

## 1. trunk 冻结：三层防护，建议上两层

### 1.1 三层手段对比

| 层 | 手段 | 能防什么 | 成本 | 副作用 |
|---|---|---|---|---|
| **L1** | 目录 ACL 拒绝写入 | **从根上改不了**（含 Unity 写入 Library） | 1 分钟 | trunk 里的 server 跑不起来（正好，用 singlegame/server）；自己仍可手动解除 |
| **L2** | 轻量清单校验（path+size+mtime） | **能发现"被改了什么"** | 2 分钟建清单，日常校验 5 秒 | 无 |
| **L3** | 独立 `.git` 基线（`--git-dir` 放在 trunk 外面） | 能看 diff、能回滚 | 20 分钟 | 7.2 GB 仓库，操作慢 |

### 1.2 推荐组合：L1 + L2

**L1 —— 设只读（一次性）**

```bat
:: 拒绝对当前用户写入 + 删除（递归继承）
icacls "I:\AINewWork\maochao_game\game_machao_new\trunk" /deny "%USERNAME%":(OI)(CI)(W,D)

:: 需要临时解除（比如回查/拷贝）时：
icacls "I:\AINewWork\maochao_game\game_machao_new\trunk" /remove:d "%USERNAME%"
```

> ⚠️ 注意：`attrib +R` 对**目录**不可靠（Windows 上目录的只读位主要给资源管理器用，拦不住写）。要真拦必须用 ACL。
> ⚠️ 这是"减速带 + 强信号"，不是安全边界 —— 你拥有这个目录，随时能解。它的价值是**让"手一抖"变成"报错"**。

**L2 —— 建基线清单**

```powershell
# 建基线（放 singlegame\docs\ 下，不进 trunk）
$root = 'I:\AINewWork\maochao_game\game_machao_new\trunk'
$ex   = @('\client\JE_WLY_Clinet\Library\','\client\JE_WLY_Clinet\Bundles\',
          '\client\JE_WLY_Clinet\Logs\','\client\JE_WLY_Clinet\Temp\',
          '\client\JE_WLY_Clinet\.vs\','\HotUpdateScripts\obj\',
          '\HotUpdateScripts\packages\','\nanoserver\build\','\Logs\')
Get-ChildItem $root -Recurse -File -ErrorAction SilentlyContinue |
  Where-Object { $p = $_.FullName; -not ($ex | Where-Object { $p -like "*$_*" }) } |
  ForEach-Object { '{0}|{1}|{2}' -f $_.FullName.Substring($root.Length), $_.Length, $_.LastWriteTimeUtc.Ticks } |
  Sort-Object | Set-Content -Encoding utf8 "$PSScriptRoot\trunk-baseline.txt"
```

```powershell
# 日常校验（5 秒级）：列出 新增/删除/改动 的文件
$root='I:\AINewWork\maochao_game\game_machao_new\trunk'
$ex=@('\client\JE_WLY_Clinet\Library\','\client\JE_WLY_Clinet\Bundles\','\client\JE_WLY_Clinet\Logs\',
      '\client\JE_WLY_Clinet\Temp\','\client\JE_WLY_Clinet\.vs\','\HotUpdateScripts\obj\',
      '\HotUpdateScripts\packages\','\nanoserver\build\','\Logs\')
$cur = Get-ChildItem $root -Recurse -File -ErrorAction SilentlyContinue |
  Where-Object { $p = $_.FullName; -not ($ex | Where-Object { $p -like "*$_*" }) } |
  ForEach-Object { '{0}|{1}|{2}' -f $_.FullName.Substring($root.Length), $_.Length, $_.LastWriteTimeUtc.Ticks } |
  Sort-Object
$base = Get-Content "$PSScriptRoot\trunk-baseline.txt"
Compare-Object $base $cur | Format-Table -AutoSize
# 没有输出 = trunk 干净
```

> 用 size+mtime 而不是 md5：46,000 个文件做 md5 要几分钟，日常用不上。**真起疑时**再对可疑文件单独做 md5。

**为什么不上 L3（给 trunk 建 git）**：7.2 GB 会让每次 `git status` 都变慢，而且要在 trunk 里放 `.git` 就等于"改了 trunk"，逻辑上自相矛盾。L1+L2 已经够。

## 2. 十条铁律逐条说明

### 铁律 1｜trunk 只读

- **为什么**：它是唯一原件；且 `productName` 与 singlegame 相同，一旦在 trunk 里 Play 就会覆盖 singlegame 的 `PlayerPrefs` 与存档目录（全项目 185 处用到）。
- **症状**：登录态莫名失效、设置被重置、存档变旧。
- **自检**：L2 清单无输出；不在 trunk 里开 Unity。

### 铁律 2｜上行只拦两处

- **为什么**：只拦截 `TCPClientMgr.SendMessage` 与 `HttpRequestHelper` 两个函数，就能覆盖全部 TCP/HTTP 上行，客户端业务代码一行不用改。一旦允许在各 UI 里写 `if (IsLocalMode)`，就会散成几十处。
- **症状**：某个界面偶尔走真网、偶尔走本地；改一处漏十处。
- **自检**：`grep -rn "IsLocalMode\|LocalServer.Enabled" --include=*.cs HotUpdateScripts/GameUI` 应该命中数很少（目前设计上只允许 UIHall / UILogin / UISelectRole 等挂载点）。

### 铁律 3｜推送只走 `UniGameEvent.Send`

- **为什么**：trunk 把 `TCPClientMgr.ProtoDeSerializePost` 里的 `JEvent.defaultEvent.Post(post)` 注释掉，换成了 `UniGameEvent.Send(post)`；`ProtoC` 也改成 `UniGameEvent.AddEventListener<T>`（145 处）。上一轮 LocalServer 有 **32 处** `JEvent.defaultEvent.Post`。
- **症状**：**编译通过、不报错、不抛异常，但所有界面一片空白**。这是最难查的一类。
- **坑中坑**：`UniGameEvent.Send<T>(T)` 按**静态类型名**派发。`localResult.Response` 是 `object`，直接 `Send(obj)` 会派到 `"Object"` 频道 → 必须 `UniGameEvent.Send(resp.GetType().Name, resp)`。
- **自检**：`grep -rn "JEvent.defaultEvent.Post" HotUpdateScripts/LocalNet` 应为 0。

### 铁律 4｜不删 UI / prefab，只隐藏 + 空实现

- **为什么**：prefab 与脚本靠 GUID 互引，删一个模块会带出一串 `Missing`；上轮就是"为了关入口去删 UI 模块，结果编译链全崩"。
- **症状**：编译报错、prefab 变紫、`Missing (Mono Script)`。
- **自检**：`git status` 里不应出现 `D`（删除）状态的 `GameUI/**` 或 `*.prefab`。

### 铁律 5｜配置走覆盖层

- **为什么**：上轮为功能锁全开直接改了 `config.xml`（客户端 48 个 module + 服务端 53 个），为补字段直接改 `partner.json`。结果原版与我方永久混杂。
- **症状**：想知道"这数值是原版的还是我们改的"时答不出来；官方更新版本时无法对比。
- **做法**：原表只读，改动写 `Assets/HotUpdateResources/Main/Other/TextAssets/single/*.single.json|xml`，加载后 merge。

### 铁律 6｜动原文件先登记

- **为什么**：53 个原文件、5,408 行补丁，靠脑子记不住。
- **做法**：`docs/CHANGES.md` 一行一条：`日期 | 文件 | 原版行为 | 改成 | 原因 | 可回滚 | ADR`。

### 铁律 7｜LocalServer 只写引擎无关纯 C#；四层分层

- **为什么**：ILRuntime 下 new MonoBehaviour / 强依赖 AOT 绑定会莫名报错；上帝类（1 万行的 LocalServer.cs）改一处崩一片。
- **四层**：Adapter（薄，只 `case → service`）/ Service（业务）/ Repository（LocalData、存档）/ Config（复用现有 CFG_*）。
- **三条子约束**：① Adapter 里零业务计算 ② Service 允许单向依赖、禁止循环 ③ 响应对象在 Service 里构造完。

### 铁律 8｜`.meta` 入库，缓存不入库

- **为什么**：`.meta` 里有 GUID，漏一个对应资源引用全断；`Library`(2.3G) / `Bundles`(202M) / `Hidden~` / `*.bytes` 是可重建二进制，入库会让仓库爆到 3 GB。
- **自检**：`git status` 干净；`git ls-files | grep -c "\.meta$"` ≈ **11,550**（`Assets/` 下实测值）。

### 铁律 9｜Unity 单开 + batchmode 前关 GUI

- **为什么**：Unity 会锁 `Library/`，两个实例同时开会互相打断导入；batchmode 与 GUI 并发会跑出假红。
- **症状**：`Unity Editor is running. Close it before batchmode.`；或测试结果飘忽。

### 铁律 10｜每包收尾能进大厅 + 打 tag

- **为什么**：单机化最怕"连续两周编译过但进不去"。有 tag 才能二分定位。
- **做法**：`tag: v0.1-runnable-hall` / `v0.2-proto-coverage` / `v0.3-webgl-playable`。

## 3. 哪些规则**不该**写进文档

写文档最大的风险是"写了没人看"。所以刻意不写这些：

| 不写 | 改用 |
|---|---|
| 代码风格（命名/缩进/花括号） | `.editorconfig` + 默认 IDE 格式化 |
| 目录里每个文件干什么 | 看代码，或写在该文件头部注释 |
| 每个接口的字段说明 | 看 `protocol/route.go` + `docs/proto-map.md` |
| 详细的业务流程描述 | 看 go 源码（权威），文档只留"位置索引" |
| 通用 Unity/ILRuntime 知识 | 不写，谁不懂谁查 |

**判断标准：这条规则违反时，能不能在 5 分钟内被发现？**
能 → 交给工具/脚本；不能 → 才写进本文档，并且要配一个"能发现"的手段。

## 4. git：现在就建

铁律 6、8、10 都依赖 git。建议第一次提交前先做：

```bash
cd /d I:\AINewWork\maochao_game\game_machao_new\singlegame
git init
git config core.autocrlf false        # ⭐ 不关的话 .meta/prefab 会天天假改动
git config core.fscache true
git config core.preloadIndex true
git config feature.manyFiles true
git config gc.auto 0
git config core.filemode false
# 然后写 .gitignore（见方案文档 §2.3），再：
git add -A
git commit -m "chore: import JE_WLY_Clinet from trunk (unmodified) + server"
```

> 第一个 commit 必须是**未经我们改造的纯净副本**——它是之后所有 diff 的原点。
